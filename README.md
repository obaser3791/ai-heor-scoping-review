## What this package contains

Everything needed to reproduce every number, figure, and table in the manuscript from a clean machine, plus the verification logs that support the reference list. The review followed PRISMA-ScR. All PubMed searches were executed on 9 September 2026 and the FDA AI-Enabled Medical Device List was retrieved current as of 4 September 2026.

Because PubMed is a living index, re-running the search on a later date will return a different record set. The retrieved records are therefore shipped in `data/` so that the analysis is reproducible independently of the search.

## Pipeline

Run from the repository root. Steps 01 and 02 require network access to PubMed; step 06 requires network access to Crossref and DataCite. Steps 03 through 05 and 07 through 09 are fully offline and reproduce every reported number from the shipped data.

| Script | Purpose | Network |
| --- | --- | --- |
| `01_pubmed_counts.py` | Retrieve the seven annual denominator series and write the query strings actually executed | Yes |
| `02_fetch_records.py` | Retrieve the review corpus records to `data/records.jsonl` | Yes |
| `03_screen_classify.py` | Apply PRISMA-ScR exclusions, deduplicate, and classify by the term dictionary | No |
| `04_agreement.py` | Compute agreement, kappa, PABAK, precision, recall, F1, and the precision-adjusted corpus | No |
| `05_figures.py` | Regenerate Figures 1 to 5 | No |
| `06_verify_dois.py` | Resolve every candidate DOI against Crossref with DataCite fallback | Yes |
| `07_build_refs.py` | Build the verified Vancouver reference library from returned metadata | No |
| `08_resolve_citations.py` | Resolve `{{c:key}}` tokens into numbered superscripts and emit the reference list | No |
| `09_build_tables.py` | Build the five main tables and the twenty eTables | No |

```bash
python3 -m pip install -r requirements.txt
python3 bibliometrics/03_screen_classify.py
python3 bibliometrics/04_agreement.py
python3 bibliometrics/05_figures.py
python3 bibliometrics/07_build_refs.py
python3 bibliometrics/08_resolve_citations.py
python3 bibliometrics/09_build_tables.py
```

## The classification dictionary and its measured error

`03_screen_classify.py` contains the complete dictionary, reproduced in eTable 2. It assigns eight non-exclusive application domains and one exclusive method category from six.

The dictionary is transparent and fast and it is also wrong in ways that are invisible unless measured, so this package ships the measurement. A simple random sample of 300 included records was re-classified by an independent large language model classifier, blinded to the dictionary output and given only title and abstract. Prompts, inputs, and outputs are in `data/`:

- `data/sample_for_llm_audit.jsonl`, the 300 sampled records as presented to the blinded classifier
- `data/sample_dictionary_labels.json`, the dictionary labels for those records, withheld from the classifier
- `data/llm_audit_labels.json`, the blinded classifier output
- `data/llm_audit_summary.md`, the prompt and procedure

Anyone may substitute a human dual review for the blinded classifier using the same sample and recompute every statistic with `04_agreement.py`. That substitution is the correct next step and is stated as a limitation in the manuscript.

## Reference verification

No citation in the manuscript was accepted without programmatic verification. `06_verify_dois.py` resolves every candidate DOI against the Crossref REST API, falling back to DataCite for preprint and dataset identifiers, and `07_build_refs.py` constructs each Vancouver reference from the returned metadata rather than from a model generated string. Of 173 candidate DOIs, 172 resolved. One failed to resolve and one resolved to an unrelated work; both were removed from the manuscript rather than cited, and both are recorded in eTable 20.

`08_resolve_citations.py` exits non-zero on any unresolved or blocked citation key, so a manuscript containing an unverified reference cannot be built.

Grey literature without a DOI, including agency guidance, position statements, conference posters, and press releases, is in `verification/weblib.json` with the issuing organization, date, and retrieval address.

## TRACE-HEOR

The manuscript proposes TRACE-HEOR, a ten item standard for Transparent Reporting of Artificial intelligence Components in health Economics and Outcomes Research, designed as an extension to CHEERS 2022 and PALISADE and aligned to the FDA credibility assessment framework and ELEVATE-GenAI. The full standard is in Table 5. Item 6, decision reversal, requires re-estimating the primary result with the AI component replaced by the pre-AI alternative and stating whether the recommendation changes. It is the item no current instrument requires.

This package is itself an attempt to satisfy items 1, 9, and 10 of the standard it proposes. The declared AI functions in this work are set out in the manuscript Disclosures.
